# POP909 001–010 Audio2MusicAOG 基线报告

实验日期：2026-09-03

## 实验定位

这是固定 `001–010` 的工程 smoke benchmark，用于验证从数据、无标签泄漏渲染、MOSS-Music 推理、MusicAOG 组图到定量评测的完整链路。十首连续编号样本不具有统计代表性，不能作为正式论文的最终测试集。

模型为 `MOSS-Music-8B-Thinking`，推理由 SGLang 提供。每首歌拆成 global、structure、harmony 三个任务；和声任务按 30 秒切片，生成预算为 2048 tokens。输入音频由 POP909-CL MIDI 渲染，但渲染前移除了和弦标签轨，避免把 Ground Truth 泄漏到模型输入。结构 Ground Truth 使用 `human_label1.txt`。

## 表示层修复

初次组图时，模型输出的零时长段落或和弦会成为非法节点，导致图有效率只有 60%，完整产物率只有 10%。组图器现会：

1. 不把非正时长观测写成图节点；
2. 在 `uncertainties` 中记录被省略观测的原始起止时间、标签和来源 ID；
3. 保留原始任务回答和审计警告，不改写模型判断。

对已保存回答做确定性重建后，图有效率由 60% 提升至 100%，完整产物率由 10% 提升至 40%，所有音乐内容指标保持不变。这是表示鲁棒性改进，不是识别准确率提升。

## 误差归因

十首中共有六首仍为 `partial`，原因是八次子任务 JSON 解析失败：global 3 次、structure 3 次、harmony 2 次。典型情况包括：Thinking 内容占满 token 预算后截断 JSON、把 `4:20` 写进数值字段、或生成过长的段落列表。

内容层面的问题更重要：和弦覆盖率达到 81.37%，但完全匹配率仅 6.05%、根音准确率仅 10.93%，说明模型给出了很多和弦，却大多与人工校正标签不符；这不是简单补全缺失输出能够解决的。段落边界 F1 仅 10.63%，也说明自由语言式听觉解释不能直接替代时间精确的 MIR 分析器。

Tempo 只在七首上产生可评测值，57.14% 是“有输出样本中的准确率”；按缺失为错误计算，相当于 4/10。当前汇总显式报告可用样本数，避免用缺失结果抬高分数。

## 定向结构化输出修复消融

新增的 `repair` 命令只重跑 JSON 解析失败的子任务，第二次生成预算为 4096 tokens，并要求用十进制秒数和更短的 JSON。原始回答保存在 attempt 1，重试回答保存在 attempt 2；`repair_runs` 记录参数和剩余失败，因此这不是覆盖原始失败记录。

```bash
python -m audio2musicaog.cli repair \
  /path/to/prediction.json \
  --base-url http://127.0.0.1:30000 \
  --max-new-tokens 4096
```

## 学术结论与下一步

这个基线支持一个有价值、且可证伪的研究问题：通用音乐理解模型擅长语义解释，但在严格时间对齐和符号事实恢复上明显不足；能否通过符号 MIR 前端与生成式 MusicAOG 后端融合，同时改善事实准确率、图一致性和解释可读性？

下一阶段按以下顺序进行：

1. **结构化输出消融**：已完成 2048-token 原始输出与失败后 4096-token 简洁重试；下一步加入受约束 JSON 解码，继续单独报告 schema success，不和音乐准确率混为一谈。
2. **节拍同步表示**：先估计 beat/downbeat，再把段落和和弦边界量化到节拍网格，减少秒级自由生成造成的漂移。
3. **混合感知前端**：用专门的 tempo/key/chord/structure 模型产生候选和置信度，MOSS-Music 负责语义解释、候选消歧和 Or 节点构造。
4. **正式评测**：预先固定更大的 train/dev/test 划分，报告 bootstrap 置信区间，并做 MOSS-only、MIR-only、融合模型和去除 Or 节点等消融。

beat-synchronous 候选图和首版 MOSS+MIR 融合已经实现，结果见 `research/MIR_FUSION_001_010_ZH.md`。下一阶段是在独立开发集上校准候选概率，并扩大正式消融测试集。
